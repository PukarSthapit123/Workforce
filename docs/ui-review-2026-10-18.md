## Part 0: Priority roadmap

### P0: Bugs and wrong data (fix first)
1. **Search loses focus while you type** on Team leave (`src/features/leave/TeamLeavePage.tsx:34-55`). Each keystroke changes the query key, `data` becomes undefined and the `FilterBar` unmounts. Notices, Cover and the Audit log have the same problem. Fix: add `placeholderData: keepPreviousData` to the filtered queries, and render filters outside the `d &&` guard. (C)
2. **Week grid labels are hardcoded Monday-first** (`src/features/timesheet/WeekGrid.tsx:24-26`). A Sunday-start tenant sees the wrong weekday names. Derive the label from the ISO date. (E)
3. **DST nights miscount hours** (`src/domain/rota.ts:47-52`, `src/domain/timesheet.ts:180-181`). On 25 Oct and 29 Mar an 8h shift is really 9h or 7h. This is a payroll-correctness decision. (E)
4. **The line manager is stored by name** (`src/features/employees/EmployeeForm.tsx:64-65`). Two people with the same name produce duplicate React keys and an ambiguous saved manager. Store the employee code. (D)
5. **Silent truncation and wrong labels.** The audit log stops at 200 rows and never shows a total. The rota gap banner shows the wrong month across a month boundary (`RotaPage.tsx:202`). The queue drops custom shift codes (`timesheet/team.tsx:13`). (E)
6. **Destructive actions with no confirm or undo:**
   - cancelling leave, removing a delegation, a shift type or a rota shift, deleting a draft notice
   - Remove in the dimension and pay-code forms
   - live notices show a Delete button that the server always refuses (C)

### P1: Things that feel broken
7. **No overlay animates at all.** `tw-animate-css` isn't installed or imported (`src/index.css:1-2`), so every `animate-in`/`zoom-in-95`/`slide-in-*` class does nothing. Install it, then tune the durations per component (A §table). (A, B)
8. **The focus ring is barely visible** (`tokens.css:154`, about 1.7:1). It disappears on the dark top bar. Use a 2px gap plus a 2px solid ring. (B)
9. **No press feedback anywhere.** Add `active:scale-[0.97]` to the base button (and include `scale` in its transition list), plus Seg, chips, the bottom bar and the clock buttons. (A, B)
10. **Pending looks the same as disabled.** There's no spinner, and `disabled={busy}` drops focus mid-mutation. Several buttons share one pending flag, so one click shows two or more spinners. (B, C)
11. **Animations on keyboard actions.** The focus ring fades in on every Tab (`transition-shadow`). The top nav crossfades on every route change. Remove both. (A)
12. **Tooltips:** each one has its own `TooltipProvider`, so later tooltips never open instantly. Use one provider at the root. Tooltips also never open on tap, so phone and ESS users see nothing. (A, B)
13. **Layering:** DropdownMenu (z-90) sits under the dialog scrim (z-100). Its SubContent (z-50) sits under the top bar. (B)
14. **Forms:** dialogs aren't `<form>`s, so Enter doesn't submit. Focus lands on the close button. Long modals lose everything on Esc. There's no unsaved-changes guard except on PolicyPage. (C)

### P2: Worst-case robustness
15. **Long emails and file names overflow** the `Fact` value (`src/ui/Record.tsx:41`), phone cards and the account menu. Add `overflow-wrap:anywhere` and `min-width:0`. (D)
16. **The modal scope badge is `shrink-0`** (`src/ui/Modal.tsx:20`), so it squeezes the title to nothing on a phone. (D)
17. **Phone layouts at 320px:**
    - the home month grid spills shift times into the next day
    - the sign-off week buttons don't wrap
    - audit JSON and URLs in notices overflow
    - queue cards with three pills overflow (E)
18. **Number formatting:** `Intl.NumberFormat` and `Intl.PluralRules` aren't used anywhere. That gives "1 days", "1 profiles", "field(s)", "1284 of 1284", and no 99+ cap on the bell badge. Add shared `fmtCount` and `plural` helpers. (D, E)
19. **Two initials implementations.** An emoji-first name produces a broken character. Use a single `Intl.Segmenter`-based helper. (D)
20. **Schema limits disagree:**
    - employee, type and dimension fields are unbounded, but export caps them at 60/80 characters
    - pay code: the form allows 12/20, the API 40/40
    - onboarding: 80/300 vs 60/200
    - `slugOf` drops accented letters and returns an empty code for a non-Latin name (D)
21. **Big lists:** the employee, contract, user, rota grid (200+) and audit lists are neither paginated nor virtualised, and each employee row mounts its own tooltip. (D, E)
22. **Hours display varies:** 37.5h vs 7h 30m vs STD 7.5h. The home day shows "-7.5h" for a future day. The Bradford meter saturates at 100. (E)

### P3: Polish and consistency
23. **Loading and errors:** about 40 screens show plain "Loading…" text and "Reload the page". Add a shared `<QueryState>` with a skeleton and a Retry button. (C)
24. **Reduced-motion rule:** the global rule (`index.css:221-225`) forces a 150ms colour transition on everything and removes all fades. It should keep fades and remove only movement. (A)
25. **Motion tokens:** `--qp-ease-out`/`--qp-ease-sheet` are defined but unused. `--qp-duration-exit` (160ms) is longer than the 150ms enter; it should be 120ms. `--qp-life-toast` and `--qp-delay-tooltip` are ignored in favour of hardcoded values. (A, B)
26. **Mobile-native details:**
    - no `-webkit-tap-highlight-color`
    - no `color-scheme`, so native pickers stay light in dark mode
    - no `theme-color`
    - no `user-select:none` on buttons
    - the bottom-bar clearance is a magic number in three places (72/72/61px) (B)
27. **Consolidation:**
    - Select and Combobox duplicate each other's classes; so do Chip and ChipButton.
    - Unused shadcn `tabs`/`badge` (including a `transition-all`) should be deleted.
    - Move `tabular-nums` into the base table instead of about 76 hand-applied cells.
    - `font-[650]` renders as 700: load the variable Inter, or use 600/700. (B)
28. **Copy:**
    - "(s)" plurals in 9 places
    - "e.g." vs "For example,"
    - "Return" vs "Send back" for the same action
    - toasts that repeat what's already on screen
    - buttons that only toast "future enhancement"
    - left-aligned numeric columns
    - the notice track dialog skips from h2 to h4 (C)

### Decisions for you (no single right answer)
- Decimal hours or HH:MM, everywhere (recommendation: one format, decimal for payroll-facing screens).
- How to pay and display DST nights.
- An overnight "+1" marker.
- What the home month view looks like on a phone (recommendation: a week list below the md breakpoint).
- Paginate or virtualise each big list.
- Truncate or wrap per field (see D/E Part 2).
- Confirm dialog or undo toast for each destructive action (recommendation: undo toast for reversible actions, confirm for irreversible ones).

### Already good (don't touch)
- **Motion done right:** the Switch and Sonner toast motion, hover gating (Tailwind v4 media-queries `hover:`), trigger-anchored origins, and Meter, route changes and row highlights staying unanimated.
- **Data handling:** UTC date parsing with tenant-zone "today", and hours rounding in the domain code.
- **Components:** the searchable picker ("Showing 50 of N"), the shared Avatar, Meter and Stats, and phone card tables.
- **Safety:** there's no `dangerouslySetInnerHTML` anywhere.

# Part A. Motion (review-animations)

## Motion review: qnipay-workforce-app

Scope: animation and motion only, across `src/index.css`, `src/ui/tokens.css`, `src/ui/**`, `src/ui/shadcn/**`, `src/shell/**` and `src/features/**` (tests excluded). Standards: `.claude/skills/review-animations/STANDARDS.md`.

**Headline finding.** None of the shadcn overlay motion classes do anything. `tw-animate-css` is not in `package.json`, and `src/index.css:1-2` imports only `tailwindcss` and `tokens.css`. In the built CSS (`dist/assets/index-B2sQtdML.css`), `animate-in`, `animate-out`, `fade-in-0`, `zoom-in-95` and `slide-in-from-top-2` each appear **0 times**. The only `@keyframes` is `spin`. So every dialog, dropdown, select, combobox and tooltip mounts and unmounts with no motion. Meanwhile the strong motion tokens `--qp-ease-out`, `--qp-ease-sheet` and `--qp-duration-exit` have **no consumers**.

## 2. Verdict

### Feel-breaking regressions
- **Overlays have no motion at all (rows 1, 3-6, 9, 10, 12).** `tw-animate-css` is not installed, so all the shadcn `animate-in`/`zoom-in` classes are no-ops. Dialogs, menus, selects, comboboxes, tooltips and the notification panel pop in and out. The bottom sheet on a phone appears without coming from the bottom edge. The strong curves `--qp-ease-out` and `--qp-ease-sheet` exist in `tokens.css:174-175` and nothing uses them.
- **Animation on keyboard actions (rows 7, 8, 9, 20-22).** Focus rings fade in over 150ms on Tab across every form field, card and rota chip. Once the overlay classes work, keyboard-opened menus, comboboxes and selects would animate as well, and the combobox and select would linger after an Enter pick.
- **Nothing gives press feedback (rows 13-17, 23, 28).** No `:active` transform anywhere, including the Clock in / Clock out CTA, the icon buttons and the phone bottom bar, where there is no hover state either.

### Missed simplifications
- Delete the exit animations on Combobox and Select (rows 8, 9), the 8px `slide-in-from-*-2` on dropdowns and tooltips (rows 6, 10), the selection crossfades on nav tabs and area pills (rows 18, 19), the input focus transition (row 20), and the dead `tabs.tsx` with its `transition-all` (row 25).

### Performance
- Mostly clean. Transitions are property-scoped (`transition-colors`, `transition-[…]`). Nothing animates width, height or top. Hover is correctly gated: Tailwind v4 compiles `hover:` inside `@media (hover:hover)`, which appears 5 times in the build. ### Accessibility
- The reduced-motion block (`index.css:221-225`) adds motion instead of removing it. It forces a 150ms colour transition onto every element, including ones that had none, so reduced-motion users see a full-UI crossfade on theme change. **Decision: Block.** Overlay motion is broken (dead classes), animation runs on keyboard actions (focus rings, and keyboard-opened pickers once motion works), no pressable element gives press feedback, and the reduced-motion rule makes things worse. All of these have small, exact fixes listed above.

- **Glyphs.** Unicode glyphs stand in for icons in several places: `▾` (Shell.tsx:300, AccountMenu.tsx:38), `›` (Inbox.tsx:80), `✓` (AccountMenu.tsx:50, Suggest.tsx:34), `+`/`–` (FormParts.tsx:80, :92, Stepper.tsx:14/18), and the bottom-bar set. Use lucide (`ChevronDown`, `ChevronRight`, `Check`, `Plus`, `Minus`) at one stroke. IconTile uses `stroke-[1.7]` (Card.tsx:24, Record.tsx:153) while everything else uses lucide's default 2. Pick one stroke (1.75) and set it once with `[&_svg]:stroke-[1.75]` in a base rule or lucide's `absoluteStrokeWidth`.

**Tokens**
- **Duplicate values under different names.** `--qp-color-text-secondary` and `--qp-color-text-muted` are identical in both themes (tokens.css:101-102, 186-187). The same holds for `--qp-color-surface-sunken` and `--qp-color-surface-tint` (:96-97, :183-184). On top of that, shadcn's `--muted-foreground` and `--secondary`/`--muted` alias them again (index.css:23-26). Code uses `text-text-muted`, `text-text-secondary` and `text-muted-foreground` interchangeably (63 uses of the latter two in src). Either make them different, or collapse to one name and alias the rest.
- **`--radius-md` and `--radius-control`.** Both map to `--qp-radius-control` (index.css:145-146). Keep one.
- **Tokens defined but not used, with literals used instead.** `--qp-delay-tooltip:400ms` sits beside `delayDuration={400}` ×5, and `--qp-life-toast:5000ms` beside `duration: 5000`. Export them from a `src/ui/motion.ts` const. These tokens are unused: `--qp-shadow`, `--qp-shadow-xl`, `--qp-shadow-2xl`, `--qp-radius-xxl`, `--qp-density-row`, `--qp-text-30/36/48`, `--qp-lh-*` px steps and `--qp-layout-*`. Prune them, or wire them into `@theme`.
- **A z-index scale belongs in `@theme`.** Values are scattered today: ActionBar 50, TabStrip 60, TopBar 70, BottomBar 80, Dropdown/Inbox 90, scrim 100, dialog 110, popover/select/combobox 120, tooltip 400, Sonner's own about 1e9, and Dropdown SubContent 50 (a bug). Define `--z-sticky:50; --z-tabs:60; --z-topbar:70; --z-bottombar:80; --z-overlay:100; --z-dialog:110; --z-popover:120; --z-tooltip:130` and use `z-(--z-popover)`.
- **The bottom-bar height is a magic number in four places.** The bar is 52px + 1px border. Clearance is reserved as 72px (Shell.tsx:151), 72px (sonner.tsx:32) and 61px (Page.tsx:46). Add `--qp-bottom-bar-h:53px` and derive each one (`calc(var(--qp-bottom-bar-h) + 8px + env(...))`).
- **Small-caps label tracking has four values** for the same role: `.03em` (table.tsx:126), `.04em` (Field.tsx:32, Record.tsx:60, table.tsx:114, Inbox.tsx:76), `.05em` (Pill.tsx:34, Shell.tsx:139) and `.08em` (GroupLabel, EssCard, FormGroupLabel, Dropdown label, RuledOutList). Add `--qp-tracking-caps:.05em` for uppercase and `--qp-tracking-label:.08em` for sentence case.
- **Arbitrary px values repeat across the primitives:** `px-[11px]` ×14, `py-[9px]` ×13, `px-[9px]` ×6, `mt-[2px]` ×6, `size-[34px]` ×4, `h-[30px]` ×4. The 11px/9px pair is the "control inset". Name it (`--qp-pad-control-x:11px; --qp-pad-control-y:9px`) and add `@theme --spacing-cx/--spacing-cy`, so `px-cx py-cy` replaces a dozen literals.
- **Dead Toaster config.** Only `toast.custom` is used (toast.tsx), so the `icons` map and the `--normal-*` style vars in sonner.tsx:34-49 never apply. `useAppTheme()` (sonner.tsx:16) reads `dataset.theme` once per render, so it isn't reactive to the toggle. Remove all three, or switch to `toast()` with `unstyled` + `classNames` so Sonner's own a11y and close button come with it.
- **Dead animation utilities.** See the motion note at the top. Either install `tw-animate-css` (and `@import "tw-animate-css";` in index.css) or strip the classes.

## Top 10 (priority order)

1. **Focus ring contrast** (rows 1–2). The global ring is about 1.7:1 and invisible on the dark top bar and on primary buttons. Keyboard users lose their place in the main navigation. This is an accessibility failure, not only polish.
2. **No press feedback anywhere** (rows 4, 33, 37–40). Add `active:scale-[0.97]` to Button, and active states to the bottom bar, icon buttons, Seg, chips and EssButton. Pair it with `-webkit-tap-highlight-color: transparent` (row 5).
3. **Tooltips** (rows 18–20). One app-level provider so skip-delay works, and a tap-to-open popover for `i`/Caution/Pill notes on touch, which today do nothing on phones.
4. **Pending vs disabled** (rows 15–17). Give `pending` a spinner and full colour, and use it in ConfirmModal and SignIn instead of `disabled`, which also drops focus.
5. **Native chrome in dark mode and the mobile meta** (rows 5–7, 50–51). `color-scheme`, `theme-color`, `user-select:none` on buttons, and dark values for the scroll shade and invalid ring.
6. **Consolidate the z-index scale** and fix DropdownMenu z-90 and SubContent z-50 (rows 21–22), before a dropdown first lands inside a modal.
7. **`tabular-nums` in the base** (rows 10–14). Put it on `<table>`, Fact, EssRow, CalNav and the bell count. It replaces 76 hand-added classes.
8. **Combobox/Select robustness** (rows 27–32). Bound the list by the available height, open on ArrowDown or typing, give it honest empty states, make phone rows 44px, and make the chevron visible.
9. **Sheet and safe-area gaps** (rows 24–26, 47–49). Use `dvh` for the desktop modal, inbox and menu, add a safe-area pad when a sheet has no footer, add notch insets on TopBar, and `overscroll-contain`.
10. **Dedupe the primitive layer.** Delete unused tabs/badge and the unused button sizes. Share the trigger and option classes between Select and Combobox, merge Chip and ChipButton, collapse the duplicate colour tokens, fix `font-[650]` (row 9, which renders as 700), and replace the unicode glyphs with lucide (row 42).

## Cross-cutting patterns (fix once)

1. **`<QueryState>` with Retry.** There are 40+ copies of `isPending → <p>Loading…</p>`, `isError → <p role="alert">… Reload the page.</p>`. Make one component that renders a sized skeleton (to avoid layout shift), an error line with `role="alert"` and a **Retry** button calling `refetch()`, and the optional refusal text. "Reload the page" is the fallback, not the instruction. Places that need it: ApprovalsPage:30-32, CalendarPage:33-35, ContractsPage:35-36, DimensionsPage:69-70, EmployeesList:57-59, AuditPage:66-71, PermissionsPage:44-56, ModulesPage:42-44, OrganisationPage:55-57, BusinessCentralPage:37-39, plus every ESS page (Home, Leave, Hours, Notices, Onboarding, Shifts).
2. **Filtered and paged queries keep the previous page.** Add `placeholderData: keepPreviousData` to `useAudit`, `useTeamLeave`, `usePostedNotices`, `useCoverBoard`, `useMyShifts` and `useRotaPlan`. On screens, never put the filter controls inside a `data &&` guard. Use `isPlaceholderData` for an `aria-busy` dim. Debounce text search by about 250ms. This removes focus loss (rows 1, 35 and 41) and flashing (row 92).
3. **Modal dirty guard and Enter submits.** Feature dialogs have no `<form>` (`grep "<form"` finds nothing in src/features). Add a `ModalForm` variant: wrap the body and footer in `<form onSubmit>` with a `type="submit"` primary button, so Enter submits. Accept an `isDirty` prop; when it is set, an `onOpenChange(false)` from Esc, the overlay or ✕ goes through "Discard changes?". Also focus the first field on open (`onOpenAutoFocus` → the first `[data-autofocus]`). Without that, Radix focuses the header ✕, which is the first tabbable element. Use in: EmployeeForm, NewTypeModal, DimensionForm, PayCodeForm, ContractsPage, EditDialog (notices), RequestDialog, ProposeChange, DelegationDialog, ChainDialog, NoteDialog, ReturnDialog, SendBackDialog and WithdrawDialog.
4. **Route-level unsaved-changes guard.** The setup pages (LeaveSetupPage:82, RotaSetupPage:179, TimesheetSetupPage:86, OnboardingSetupPage:56, NotificationsPage:40, PatternEditor:90) all track `dirty`, but only PolicyPage guards navigation, and only its own links. App.tsx uses `<BrowserRouter>`, so `useBlocker` isn't available. Either move to `createBrowserRouter`, or add a `useUnsavedGuard(dirty)` that sets `beforeunload` and intercepts shell NavLink clicks through context.
5. **`useUndoableDelete` instead of instant deletes.** Make a hook that hides the row optimistically, shows `toast('X removed', { action: { label: 'Undo' }, duration: 6000 })`, and sends the DELETE only when the toast is dismissed. Where a delete can't be undone server-side, use `ConfirmModal danger`. Places: LeavePage:120, ApprovalsPage:149, ShiftCatalogue:108, DimensionForm:72, PayCodeForm:67, EmployeeTypesPage:88, TeamNoticeDialogs:104 and RotaPage:244. The `toast.tsx` helpers need an `action` option for this.
6. **Per-action pending.** `useRecordMutation` exposes `anyPending`, and screens pass it to every button: Save and Submit (DayView), Save draft and Post (notices), Remove and Save (forms), every Assign (rota and cover), every clock button, every module switch. Add `isPendingVar(vars)`, or have screens track the clicked action, so only the pressed button spins and the others are `disabled`.
7. **Toast discipline.** (a) Add a `changedToast(name, n)` and a `plural()` import everywhere `(s)` appears: EmployeeForm:98, ContractsPage:68, DimensionForm:43, EmployeeTypesPage:63, PayCodeForm:46, TeamDialogs:29 and 62, Dialogs:175 and PatternEditor:329. (b) Don't toast state the user can already see: location switched, suggestions dismissed, row added or removed, draft stage added, onboarding step saved, blur-save. (c) One toast per action: PatternEditor:51-52 and the BusinessCentral dispatcher. (d) Keep the first line under about 60 characters and put the rest in `next`. (e) Refusals are currently toasted and also shown inline as FormWarn plus a field error (`useRecordMutation` onError). When a form displays `refusal` inline, skip the toast; add an `inline: true` option to the mutation.
8. **Unbuilt features look the same everywhere.** Live buttons that only toast "future enhancement": MyShiftsPage:52-58, CoverPage:173, Dialogs:245 and PatternUpload:31. Make a `<NotBuiltButton>` that renders disabled with the existing "Future enhancement" pill (ModulesPage:166), or hide these buttons.
9. **Disable with a reason rather than refuse after the click.** Required reasons (SendBack, Withdraw, Decline, Lifecycle), impossible actions (Clear or Repeat an empty week, Copy yesterday on day 1, removing in-use records) and duplicate pickers (Delegation). The `disabled + title` pattern used at DayView:167/179/180, PatternEditor:231-234 and PayrollReadinessPage:94 isn't reachable by keyboard or touch. Use a visible hint line, or `aria-disabled` plus `aria-describedby` text.
10. **Live result counts.** `Count` (EmployeesList:54, ExceptionsPage:68, RotaPage:218, TeamLeavePage:54) changes as the user filters but isn't announced. Give `Count` `role="status" aria-live="polite"` once, in src/ui.
11. **Stable keys for editable lists.** ApprovalDialogs:53/62 and TimesheetSetupPage:328 use `key={i}` on rows that can be removed. Give each draft row an id when it is created.

## Part 2: Decisions for you

- **1,000+ rows: paginate or virtualise?** I recommend **server pagination at 50 with "Showing 50 of 1,284"** on Employees, Contracts and Permissions users. Filters are already server-side (`q`, `state`), and BC will page anyway. Virtualising a records table that becomes cards on phones is costly.
- **Line manager: name or code?** I recommend **code**. Names collide and change, and BC references people by number. This is a contract change (`employees.ts:12`) and needs a mapping in the proxy, so it belongs on the BC backend list.
- **Long names in list cells: wrap or truncate?** I recommend **wrap** for names, because people need the full name to identify someone. **Truncate with a title** for secondary columns such as department, location and BC element on desktop tables.
- **Email under a name: wrap or middle-truncate?** I recommend **`overflow-wrap:anywhere`** for now. Middle truncation is nicer for shared long domains, but it needs a helper.
- **What "Shown in the top bar" promises.** The Company profile tip says the organisation name is shown in the top bar (`OrganisationPage.tsx:320`), but `TopBar.tsx:9-14` shows no organisation name. Either show it (truncated, with a title, hidden below `md`) or change the tip.
- **Initials for one-word names** ("Sajin", "Jo"): one letter, or the first two letters ("SA")? I recommend **one letter**, which is honest and is what most products do. Pick it once in the shared helper.
- **Missing manager or email**: the "—" placeholder is fine in a `Fact` row, which keeps row heights even. The orphaned "—" inside a joined subtitle (#10) should be dropped instead.
- **Field limits**: pick one source of truth. My suggestion is the Zod contract, with `maxLength` derived from it. Choose numbers that match the BC fields the proxy will write to (Name 100, E-Mail 80, Code 20).

## Part 3: What held up

- **Searchable pickers at scale.** `Combobox` draws at most 50 matches with "Showing 50 of N. Type to narrow down." (`Combobox.tsx:9,104-106`). The manager picker over 1,284 people stays usable.
- **Records tables on phones.** The `records` variant becomes labelled cards, and `empty` hides blank optional cells such as Manager and End (`EmployeesList.tsx:85`, `ContractsPage.tsx:54`). Desktop tables scroll sideways inside a rounded container with scroll shades, and the matrix pins its first column.
- **Shrink discipline.** `Avatar`, `IconTile`, permission cells, the dialog close button and the setup card count pills are all `shrink-0`. The text columns in `EmployeeBlock`, `SetupCardButton`, module cards and inbox rows have `min-w-0`.
- **Pills.** `Pill` is `whitespace-nowrap` and carries a glyph and a label, so a status never wraps or relies on colour alone.
- **Dates.** Every date goes through the tenant's format (`formatDmy` / `formatDateTime`), and a blank date shows "—". No raw ISO strings or `1970-01-01` leak.
- **Money and negatives.** By design there is no money on these screens. Pay code values are limited to 5 characters and refuse currency and negatives (`contract/pay-codes.ts:20`). Hours are held to 0–80 (`domain/employees.ts:24`).
- **Existing plurals done right.** "Held by 1 employee" (`EmployeeTypesPage.tsx:87`), "1 entry" (`DimensionsPage.tsx:30`), "1 thing still to do" (`OnboardingPage.tsx:213`), exception counts (`PermissionsPage.tsx:17`), `usagePhrase` nouns, and the setup page count for screen readers.
- **Bounded repeaters.** Emergency contacts are capped at 5, qualifications at 10 and documents at 20, and the template, policy and signature inputs carry `maxLength`. Role names are capped at 24, so the `whitespace-nowrap` matrix header stays sane.
- **Escaping.** There is no `dangerouslySetInnerHTML` in `src/`, so `<script>` and `&amp;` in names render as literal text.
- **Empty and error states.** Employees ("Nobody matches that filter."), Dimensions, Modules search, Inbox ("Nothing new"), team onboarding (names the location), and a loading and error line on every screen.
- **Unknown manager.** A manager that is not an employee (the seed has "Eddie Harford" and "Manish Nepal") still shows: the Combobox renders the raw value when it is not among the options (`Combobox.tsx:76`).

## Part 2: Decisions for you

- **D1. Decimal vs HH:MM.** Hours today mixes `37.5h`, `7h 30m` and `07:30`. I recommend tenant `timeFormat` (`formatMinutes`) for everything an employee sees, with decimals only in Pay elements and exports, because payroll reads decimals and people read clock time. (#21)
- **D2. DST nights.** Pay actual elapsed hours (9h / 7h) or rostered hours (8h)? UK practice usually pays actual. I recommend computing elapsed hours from zoned instants and showing a "Clocks change tonight" advisory on the cell. (#3)
- **D3. Overnight marker.** "+1", "(next day)" or an arrow glyph. I recommend "+1" in compact cells and "next day" in the aria-label and dialogs. (#14)
- **D4. Home month on a phone.** Squeeze the content in or simplify it. I recommend code + glyph only at `max-md`, with time and hours in the day dialog. The grid then stays a calendar, and the dialog already carries the detail. (#2)
- **D5. 200+ rota rows.** Virtualise or paginate. I recommend paging by job profile or filter by default, plus row virtualisation later. Managers read the grid by team, and drag-and-drop over virtualised rows is fiddly. (#29)
- **D6. Audit size.** Show "200 of 1,284" with Load more, or require a filter above N. I recommend Load more with a visible total. (#5)
- **D7. Bradford meter scale.** Fill relative to the tenant trigger (100% = trigger) or show no bar over the trigger. I recommend relative to the trigger, with the bar red once it reaches 100%. (#11)
- **D8. Bell cap.** I recommend "99+" visually, with the exact count in the aria-label. (#18)
- **D9. Rota grid name column (172px).** Wrap or truncate. I recommend keeping the wrap (it identifies the person) and adding `overflow-wrap:anywhere` for unbroken names. Row heights then vary, which is acceptable.

## Part 3: What held up

- **Date handling is sound.** `parseIso`/`toIso` work in UTC (`src/domain/time.ts:67-73`), and there is no `new Date('YYYY-MM-DD')` anywhere in scope. "Today" comes from the tenant zone (`src/lib/format.ts:17`, `clockAt`). Dates go through `formatDmy` in the tenant format.
- **Week start is honoured outside WeekGrid.** The home month uses `weekHeads()` plus server `leadingBlanks` from `dayIndex`, and a 6-week month just adds a 6th auto row. TeamMatrix labels days with `dowMon`. The rota grid uses `weekHeads()`.
- **Rounding.** Hours use `r1`/`r2` in the domain and team totals are rounded (`src/domain/hours.ts:86-95`), so no `0.30000000000000004` was found. `varianceText` signs correctly and `-0` renders as "+0".
- **Primitives.**
  - `Avatar` is `shrink-0`, and its initials skip repeated spaces.
  - `Meter` clamps 0–100.
  - `Stat`, `Meter`, `Count` and the numeric cells use `tabular-nums`.
  - `Stats` uses `minmax(min(100%,190px),1fr)`.
- **Tables on a phone.** Records tables become labelled cards on phones. Matrix and plain tables scroll with a pinned first column and scroll shades. My leave `RequestRow` gets `min-w-0`/`shrink-0` right.
- **Plurals already handled.** Sickness ("1 day"), triggers and colleagues counts, awaiting weeks, plan "shift(s)", leave-setup `daysText`, notice acknowledgement banner, ActionBar "1 change", TeamMatrix toast.
- **Leaver reconciliation.** It uses `Math.abs(diff)` with absolute hours, so there is no "-15 hours".
- **Clock ring.** `ringTarget` defaults to 8h, so a bank day with no rota cannot divide by zero.
- **Escaping.** There is no `dangerouslySetInnerHTML` in `src`. Notice bodies render as text with `pre-wrap`.
- **Empty states exist** for the queue, sickness, hours, notices (both sides), exceptions, audit, delegations, cover, rota changes and the rota key ("No shifts on this week yet").
- **Payroll and Business Central render no money at all.** GBP formatting, negative amounts and large values do not apply here, because Workforce posts hours and codes only.
- **Rota row header** (172px) wraps hyphenated names at the hyphen, and `hoursLine` stays on one line.
- **Not-built and unavailable pages** are simple. The unknown path uses `break-all`; `overflow-wrap:anywhere` would be slightly nicer, but it does not break.
